# Contributing

1. Read README.md and run locally using synthetic data.
2. Create a branch for a focused change. Explain the problem in an issue when useful.
3. Add tests for behavior changes and run the README checks.
4. Submit a pull request with a summary, verification steps and screenshots for UI changes.

Keep credentials, personal/medical data, uploads, logs, node_modules and private
report documents out of commits. Use environment examples with empty secrets.
Database changes need a migration and notes about compatibility and backups.

Report security issues privately using GitHub's Security tab if private reporting
is enabled. Otherwise contact the repository owner privately before sharing exploit
details. Do not open public issues containing credentials or patient information.
